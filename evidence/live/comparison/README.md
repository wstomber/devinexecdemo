# Stage 4 comparison evidence

Generated by `make build generate && python3 tools/side_by_side.py` (COBOL
`build/msp-batch` vs `python3 python/msp.py`). The `tools/verify.py` runs are
in `../stage4-verify.log` and the `*-report.json` files here.

| Batch | Records | MATCH | MISMATCH | Totals | Results/totals files byte-identical |
|---|---|---|---|---|---|
| [curated](curated/side-by-side.md) | 33 | 33 | 0 | match | yes |
| [synthetic](synthetic/side-by-side.md) (seed 20261017) | 1,000 | 1,000 | 0 | match | yes |
| [edge](edge/side-by-side.md) (seed 20261020, adversarial) | 3,000 | 3,000 | 0 | match | yes |
| [fatal paths](fatal/fatal-paths.md) | 21 cases | 21 | 0 | - | - |

Each batch folder keeps `input.dat`, `cwf.dat`, both programs' raw
`*-results.csv`, `*-totals.csv`, `*-stderr.txt`, and `side-by-side.csv/.md`.
`summary.json` has the machine-readable counts and totals.

The edge batch mixes boundary amounts (0, 1, 9,999,999,999), random byte
mutations (lowercase, `+`, NUL, 0xFF, tab, CR, form feed), short/long/blank and
4,096-byte lines, LF/CRLF endings and a last line with no LF, malformed
contracts, dates and MBIs, and CWF quirks (CR inside a record, bytes after
column 64, a second `B` record for the same MBI, a NUL inside an MBI).

Limits: parity shows the Python matches the COBOL on these batches. It is not
proof of Medicare correctness, and untested inputs may still differ.
