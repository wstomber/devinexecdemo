This map separates selected CMS payment rules from the fixed-width batch contract
and other demo choices. The source review and interpretation are recorded in
[`docs/rules.md`](../rules.md); page numbers below are one-based PDF viewer pages.
Line references point into this repository's files at this Stage 5 documentation
commit.

`tests_policy/expectations.json` contains the independent Stage 2 ledger IDs.
`test_batch_interface.py` names are the executable interface cases. Stage 2 ran
against COBOL before Python existed; Stage 3 ran the same suite against Python.
Observed outcomes cite the corresponding retained logs and, where useful, the
per-record comparison report.

## Demo interface assumptions are not CMS policy

These choices define this small batch interface; they are not Medicare rules or
CMS edit/reason codes:

- The 73-byte record layout, ASCII text encoding, ID character set, ten-digit
  integer-cent fields, `----------` absent-contract sentinel, `Y`/`N` flag,
  validation order, provisional `@` IDs, LF/CRLF framing, 4,096-byte and
  10,000-record limits, duplicate-ID fatal behavior, CSV widths, and exit code 2.
- The optional contract is accepted only when `A <= C`; explicit zero and equality
  are valid interface decisions. A malformed contract is `BAD_AMOUNT`.
- The `PAYMENT_IN_FULL`, `PRIMARY_AT_CAP`, `DEDUCTIONS_AT_CAP`, and
  `SECONDARY_PAYABLE` labels and their precedence among valid zero cases.
- Eligibility, coverage, pricing, the correct allocation of primary payment, and
  applicable deductions are treated as upstream inputs. No beneficiary-liability
  calculation is implemented.

The CMS-derived selected formula is limited to the interpretation recorded in
[`rules.md`](../rules.md): §40.8–40.8.3, with the four limits and the obligatory
acceptance amount replacing charges. This program is not CMS production software,
not a complete claims processor, and not an exhaustive statement of Medicare
policy.

## Published Example 4 is excluded

`docs/rules.md` identifies a contradictory extra intermediate equality in the
published Example 4 on PDF page 84: the stated deductible/coinsurance facts yield
$4,600 at the cited gross-minus-coinsurance step, but the text appends an
inconsistent equality to $3,822. The discrepancy is documented as a source-review
issue; Example 4 is not used as an authoritative fixture and its inconsistent
number is not encoded as application behavior. The hand-derived ledger instead
uses unambiguous published Examples 1 and 3 (`docs/rules.md`, “Published
inconsistency”).
